## §1 架构总览

三块：**前端**（React，浏览器里跑）、**后端**（FastAPI，管数据与配置）、**go2rtc**（摄像头转流）。

```
浏览器
 ├─ /                     → 前端静态页      (dev: CRA 3000 · prod: nginx 5123)
 ├─ /api/...              → 后端 5124       (所有业务接口)
 ├─ /api/plugin-assets/.. → 后端 5124       (插件 bundle 静态托管)
 ├─ /api/upload/...       → 后端 5124       (上传的图片 / 视频)
 └─ /go2rtc/...           → go2rtc 5125     (摄像头播放页 + API)
```

### 端口

| 端口   | 谁              | 说明                                |
| ---- | -------------- | --------------------------------- |
| 3000 | CRA dev server | **仅本地开发**用，生产不存在                  |
| 5123 | nginx          | 生产入口（面板静态页 + 反代 `/api`、`/go2rtc`） |
| 5124 | FastAPI        | 后端                                |
| 5125 | go2rtc         | API（base_path `/go2rtc`）          |
| 5126 | go2rtc         | RTSP                              |
| 5127 | go2rtc         | WebRTC                            |

### 配置选择机制

后端靠 `is_running_in_docker()`（检查 `/.dockerenv`）自动选配置：

- **非 Docker** → `backend/config/dev.toml`（数据落在 `data/hass-panel-dev/`）
- **Docker** → `backend/config/prod.toml`（数据落在 `/config/hass-panel/`）

## §5 插件系统

**目标**：像装插件一样给面板加新卡片，不用改代码、不用重新构建。

**一个插件就是一个文件夹**：

```
plugins/<id>/
  manifest.json   # 元数据
  plugin.js       # 预构建好的 bundle（前端运行时 import）
```

**`manifest.json` 关键字段**：`id` `name` `version` `author` `cardType` `icon` `group` `defaultHeight` `configFields[]` `entry`

**加载链路**：

1. 后端 `routers/plugins.py` 扫描目录 → `GET /api/plugins`（**只返回启用的**）
2. 前端 `plugin/loader.js` 拉清单 → `import(entry)` → `registerCard(cardType, 组件)`
3. 宿主能力通过 `plugin/bridge.js` 挂到 `window.HassPanelBridge`，插件从 `hass-panel-sdk` 具名导入

**bundle 地址**：`/api/plugin-assets/<id>/<entry>`

> ⚠️ 刻意挂在 `/api` 下：dev 的 CRA 代理与 prod 的 nginx 都必然转发 `/api`。用 `/plugins` 前缀时，dev server 未重启（代理未加载）会回退成 index.html，插件 `import()` 到一段 HTML 而加载失败。

**管理接口**：`GET /api/plugins/all`（含禁用）· `POST /api/plugins/{id}/rename|enable|disable` · `DELETE /api/plugins/{id}`

**卡片管理**（`components/CardManagerModal/`，入口按钮「卡片管理」，图标 `mdiCardsOutline`）：
  
布局参考「全局配置」——两个**折叠分区**（默认都收起），「基础卡片」与「插件卡片」。
  
基础卡片可 **重命名 / 启用禁用 / 恢复默认名**；插件卡片可 **重命名（= 插件名）/ 启停（整包）/ 卸载**。

**接口**：`GET|POST /api/plugins/card-names`（显示名覆盖）· `GET|POST /api/plugins/card-disabled`（启用禁用）。
  
两表都存在 `plugins_state.json` 的 `cardNames` / `cardDisabled` 键里；前端由 `plugin/loader.js` 的 `loadCardSettings()`
  
一次拉取，挂到 `window.__HASS_PANEL_CARD_NAMES__` / `__HASS_PANEL_CARD_DISABLED__` 并广播 `hasspanel:plugins-loaded`。

**禁用的效果**：① 不出现在「添加卡片」列表（`AddCardModal` 里过滤 `config.disabled`）；
  
② 已放在主页 / 下拉屏的实例由 `pages/home/index.js` 的 `renderCard()` 渲染成「已禁用」占位（**不渲染真实组件，顺带省性能**）。
  
`getMergedCardTypes()` 只给每张卡片**打 `disabled` 标记、不删条目** —— 删了会让「编辑卡片」拿不到类型定义。

> ⚠️ 「添加卡片」列表的显示名走 `AddCardModal` 里的 `config.name`，而 `config.name` 由 `pages/config/index.js` 的 `getMergedCardTypes()` 用 `utils/cardTranslation.js` 统一算出来。


> 以前 `AddCardModal` 自己用 `type.replace('Card','').toLowerCase()` 查 `cardTitles`，导致驼峰卡片（PcMonitorCard / WashingMachineCard …）显示成 `cardTitles.xxx` 原文 —— 所以 `cardTitles` 里才被迫同时写驼峰和小写两份。**新卡片不要再依赖这个，直接靠 `cards.<key>` 兜底即可。**

**开发工具**：`plugin-dev/`（`build.mjs` 用 esbuild 打包，`src/index.jsx` 是模板）

**已有示例插件**（都在 `plugin-dev/` 下，各自有 `manifest.json` + `src/index.jsx` + `dist/plugin.js` + 可上传的 zip）：

| 目录            | cardType               | 用途                                                    |
| ------------- | ---------------------- | ----------------------------------------------------- |
| `notify-pro/` | `NotifyHistoryCardPro` | 消息通知升级版：复用宿主 `useNotifyStore`（SSE/未读/分页），按卡片高度自动算每页条数 |

> 「电脑监控」卡片（`PcMonitorCard`）最早也是按插件做的，后来**已改为内置卡片**（见 §0 / §7），插件目录已删除。

**`configFields` 的 type 只能用宿主 `components/ConfigField/index.js` 已支持的**：
  
`text` / `number` / `switch` / `image` / `entity` / `entity-multiple` / `group-select`，
  
以及内置卡片专属的 `nas-config` / `server-config` / `pve-config` / `router-config` / `electricity-config` 等。
  
（后几种的字段列表**写死在组件里**，插件复用得拿它已有的字段；需要自定义字段就得改宿主 `ConfigField` 并重建前端。）
  
`group-select` 的 `groups` 由 `pages/config/index.js` 在合并插件目录时自动补齐，manifest 里不用写。

## §6 部署与构建

### 本地开发

```bash
start-all.bat        # 一键：后端 + 前端 + go2rtc，并打开浏览器
start-backend.bat    # 仅后端（5124）
start-frontend.bat   # 仅前端（3000）
```

### 硬约定（踩过坑的）

1. 前端接口路径**不要带 `/api` 前缀**。
2. 插件 bundle 走 `/api/plugin-assets/...`，**不要用 `/plugins`**。
3. **密钥/Key 绝不写进源码**（会进 git）。高德 Key 存在「全局配置 → 地图」，运行时读 `window.globalConfigCache.amapKey`。
4. 提交前先扫明文密钥，**不要无脑 `git add -A`**。
5. 插件里不能用 `import Icon from '@mdi/react'`（是 Proxy，会报 `Element type is invalid`），必须从 `hass-panel-sdk` 具名导入。
6. 卡片内部要做滚动的容器，要检查 `pages/home/style.css` 里 `.base-card > div:not(.card-header) { overflow: visible }` 这条全局规则，用更高优先级 + `!important` 覆盖。
7. 后端是**定制 starlette**：`app.routes` 里看不到普通 `APIRoute`，路由包在 `_IncludedRouter.original_router.routes` 里。
8. **未经当次明确同意，不要 push 到 GitHub。**
